## Principle 6 in detail

- **6a. `compress-files` and `extract-archive` reported partial work as success.** Probed on the v1.0.0 binary:
  - `llm-filesystem compress-files --output out.zip --paths a.txt,missing.txt` prints `files_added: 1`, `success: true` and exits 0, with no mention that `missing.txt` was never added. The archive exists and holds only `a.txt`.
  - `extract-archive` had the same failure class: entries not written were not reported, and a partial run exited 0.

  This is the partial-failure finding epic 04 was created for, and it is the reason the "nothing may report success when it did not succeed" rule exists. Closed on `main` by epic 04: `fix(extract-archive): report every entry not written; exit 1 on a partial run` (`#24`) and `fix(compress-files): report every input not added; exit 1 on a partial run` (`#25`), with docs in `#27` and an end-to-end test in `#28`. The fixes are **not** in the audited v1.0.0 binary; they shipped in v1.0.1.

- **6b. `create-directory` on an existing directory reports `created: true`.** Probed: a second `create-directory --path <same dir>` prints `created: true` / `Directory created successfully` and exits 0, though nothing was created. The mutation itself is idempotent (`os.MkdirAll`, `internal/filesystem/core/write.go:337-338`), but the report claims work that did not happen — the same failure class as 6a. Still present on `main` at the time of the audit; neither epic 04 nor 05 had a task for it, so it was filed as tech debt (TD #39). Fixed after the audit (PR #38): `CreateDirectory` checks for the directory before `MkdirAll`, and a repeat run now reports `created: false` / `exists: true` with `Directory already exists: <path>`. Like 6a, the fix is **not** in the audited v1.0.0 binary; it shipped in v1.0.1.

Idempotency of the remaining mutations was spot-checked, not exhaustively probed: `delete-file` without `--confirm` changes nothing (probed).
